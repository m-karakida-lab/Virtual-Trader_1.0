# ADR-003: ドラッグ操作中のストア書き込み方針（用途で使い分ける）

## 状況
チャート上のドラッグ操作（水平線・垂直線・注文・TP/SL・draft値）を実装する過程で、ドラッグ中に毎フレームZustandストアを更新すると、Reactの再レンダリングが絡んで「カクつく」問題が起きた。一方でdraft値（発注前のpreview）は、ストアと連動した別の描画（RRボックス等）が複数あり、ストアを経由しないと同期が崩れる。両者で異なる対処をした。

## 決定
- **確定済みオブジェクト**（水平線・垂直線・既存注文・既存ポジションのTP/SL）: ドラッグ中はストアを経由せず、`IPriceLine.applyOptions()` や DOM の `style.left` を**直接操作**。`mouseup` で初めてストアにコミットする
- **draft値**（発注パネルの price/TP/SL入力）: ドラッグ中も**毎フレームストアに書き込む**（`setDraftPrice`等）。RRプレビューや入力欄の表示が自動で追従するメリットが、再レンダリングコストを上回ると判断した

## 理由
- 確定済みオブジェクトは更新頻度が高く、対象が多くなる可能性がある（複数ポジション等）ため、Reactの再レンダリングを避けたかった
- draft値は同時に存在するのは最大3つ（price/TP/SL）で、関連する描画（プレビュー線・RRボックス・Controls入力欄）が複数箇所にまたがるため、直接DOM操作で個別に同期するより、ストアの単一ソースに任せて既存のuseEffectに任せる方がシンプルだった

## 影響
- 新しくドラッグ可能な要素を追加する場合、「個数が多くなりうる確定済みデータ」か「draft的な単発の値」かで、上記どちらの方針を踏襲するか判断すること
- `CandleChart.tsx` の `DragTarget` 判別ロジックに新しい種別を追加する場合は、`priceLineMapFor()` と `findPriceTargetNear()` の両方を更新する必要がある
