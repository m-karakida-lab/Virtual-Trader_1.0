# ADR-002: 同一バーでTP/SL両方ヒット時はSLを優先判定する

## 状況
1分足を4H等に集約しているため、1本のローソク足の中で価格がTPとSLの両方のレベルを通過するケースが起こりうる（高安レンジ判定のため）。実際の値動きの順序（TPが先かSLが先か）はティックデータがないと分からない。どちらを優先して約定させるか決める必要があった。

## 決定
**SLを先に判定する**（同一バーで両方ヒットしていたら、SL価格で決済したものとして扱う）。

## 理由
- TPを先に約定したと仮定する楽観的な判定は、バックテストの成績を実態より良く見せてしまうリスクがある
- SL優先は「不利な方を先に通った」という保守的な仮定であり、練習ツールとして過信を生みにくい
- ランダム判定や「値幅が近い方を優先」のような複雑なロジックも検討したが、実装・説明のコストに対して効果が薄いと判断した

## 影響
- `processOrderRange()`（`src/lib/orderMatching.ts`）内でSLチェックがTPチェックより先に書かれている。このif-else順序を変えると挙動が変わるので、修正時は意図的かどうか確認すること（`orderMatching.test.ts`で検証）
- 1分足のまま検証したい場合（高安の粒度を上げたい場合）はこの問題自体が縮小する。時間軸を1Hなど細かくするのがユーザー側の回避策になる
